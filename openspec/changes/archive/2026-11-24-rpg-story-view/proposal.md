# Proposal

## Why

目前的遊戲畫面（`/game/<存檔識別碼>`）是聊天式的長時間軸：AI 的一整輪回應（350 至 1000 字）擠成一個大氣泡，玩家要自己捲動閱讀，也沒有任何「下一步可以做什麼」的線索。這與平台想要的「電影感、文字雜誌風」的沉浸式閱讀不符，新手常卡在空白輸入框前。使用者提供的參考影片（`影片/001.mp4`）是視覺小說式的介面：全螢幕氛圍背景、劇情分成短段落逐段點擊翻頁、結尾才出現可選的行動與輸入框。

功能操作示範影片已完成（2026-11-22），可以開始這項改版；遊戲畫面相關的四支影片會在改版完成後重錄。

## What Changes

- **視覺小說式閱讀**：遊戲畫面改為「一次一段」的劇情卡，疊在純 CSS 的深色漸層氛圍層上，氛圍層有疏落劃過的流星作為動態效果（純 CSS 動畫，不使用圖片，圖片 v1 不實作；偏好減少動態時取消）。AI 回應（含第 0 幕）依句子切成每段 2 至 3 句（單段超過約 150 字再切），字體放大，說話者標籤為「旁白」與「你」。
- **翻頁與打字機**：點擊卡片或按鍵（空白鍵、Enter、右方向鍵）翻到下一段；`‹`（與左方向鍵）只能在**當前輪**內回上一段，第一段停用。打字機改為以「段」為單位：打字中第一下點擊補完該段，第二下才翻頁。串流期間後端文字照常到達，玩家以自己的節奏翻頁。
- **歷史**：新增「歷史」按鈕，開啟只讀、純文字、單純捲動的全文（第 0 幕與已載入的各輪）；不做跳到某一輪。原本的聊天式時間軸退場，主畫面只顯示當前輪。
- **直接推進劇情**：不做空白送出；改在劇情卡下方（桌機左側另有捷徑）放「直接推進劇情」按鈕＝送出固定文字「推進劇情」。它是一般行動：預扣 30 幣、可重新生成與編輯；固定 system_instruction 加一句平台規則，行動恰為「推進劇情」時依最近 10 輪、記事簿與世界狀態自然推進。
- **建議回應（點小 icon 才產生）**：劇情卡旁放一個小燈泡 icon，**預設只顯示 icon，不產生任何建議**；玩家點開才由後端做一次**獨立的**模型呼叫（RPG 用途的模型，非串流 JSON），回 3 個行動建議。第 0 幕與每一輪都可使用；**每個畫面最多產生 1 次**（沒有「換一組」），結果存在存檔上，重開 icon 直接重用；點建議＝貼進輸入框（取代原內容、游標在尾端）、不直接送出，並收回成 icon。**不扣遊戲幣**，但記入 `llm_call_logs` 與全站每日 token 上限。
- **後端**：新端點 `POST /api/game/sessions/<id>/suggestions`；新服務（提示詞、驗證、規則層）；存檔新增可為空的 `suggestions_json`（遷移 `0023`，expand 階段）；存檔快照帶出目前有效的建議；新增 `llm_call_logs` 用途 `rpg_suggest`；個人資料匯出涵蓋建議。**狀態呼叫與串流事件協定都不改**（建議不併入每輪的狀態呼叫）。
- **規範修訂**：AGENTS.md 第 5、6、7、10、11 節最小改動，並同步 `python-flask-skill` 的對應 reference（見 design）；這份修訂在 apply 的第一批做，須先經使用者確認。
- **不在範圍內**：`自動` 與 `x2` 按鈕；空白行動送出；跳到某一輪的歷史導覽；背景圖片；建議的「換一組」與每輪多次產生；建議開關存 localStorage（改成 icon 的點開機制取代）；第 0 幕以外的存檔層級建議；玩家主動修改 NPC 角色卡。
- 無 **BREAKING** 的對外 API 變更；前端的時間軸呈現與其測試為內部重寫。

## Capabilities

### New Capabilities
- `rpg-story-pages`: 視覺小說式的分段閱讀：依句分頁的規則、閱讀狀態機（段索引、當前輪回翻、打字機補完與翻頁、串流中逐段到達）、點擊與鍵盤操作、氛圍背景層、說話者標籤、歷史只讀全文、桌機左欄捷徑與手機版面。
- `rpg-suggestions`: 玩家點 icon 才產生的行動建議：端點與前提檢查、獨立的模型呼叫與提示詞（只用玩家看得到的資訊）、逐項驗證與規則層、每個畫面 1 次的上限與存檔層保存、不扣幣但計入 token 與帳本、icon 與建議 chips 的互動、貼進輸入框。
- `rpg-advance-action`: 「直接推進劇情」：固定行動文字、前端按鈕與捷徑、系統指令的平台規則、與扣幣、重新生成、編輯及規則層的關係（等同一般行動）。

### Modified Capabilities
- `rpg-game-screen`: 「劇情時間軸與歷史補齊」改為「當前輪的分段劇情卡＋歷史全文」；「載入順序」補第 0 幕也以分段顯示；「行動輸入」補建議貼入與推進按鈕的位置；移除「回到最新」按鈕的要求。
- `rpg-stream-client`: 「打字機渲染」改為以段為單位的逐段渲染，`done` 之後補完最後一段；轉場與中斷處理沿用，但顯示位置改為劇情卡。
- `rpg-turn-context`: 固定的 system_instruction 新增「行動恰為『推進劇情』」的平台規則（平台常數，不是玩家文字）。
- `rpg-revision-ui`: 重新生成與編輯按鈕改在劇情卡下方（只對最後一輪），不再是氣泡下方；其餘行為不變。
- `rpg-sessions`: 存檔新增 `suggestions_json` 欄位（可為空）與存檔快照的 `suggestions` 欄位；陳舊判斷以錨點（最後一個完成回合的序號與修訂，或第 0 幕）。
- `personal-data-export`: 存檔匯出涵蓋目前保存的建議文字。

## Impact

- **後端**：`app/services/rpg_suggest_prompt.py`（純函式：提示詞、結構 schema、逐項驗證）、`app/services/rpg_suggest_service.py` 或併入 `game_service.py` 的方法（前提檢查、錨點、呼叫與保存）、`rpg_prompt.py`／`rpg_context.py`（推進規則、建議上下文）、`game_api_controller.py`（新端點）、`session_repository.py`（條件式寫入建議）、`models/rpg_session.py`、`models/llm_call_log.py`（新用途與 `TRADITIONAL_KINDS`）、`personal_export_service.py`、`observability/rpg_events.py`（白名單事件）。
- **遷移**：`0023`：`sessions.suggestions_json`（JSON、可為空，無預設）。舊版程式在新結構上照常運作；新版程式在舊結構上不要求運作。需同步 `docs/project資料結構文件.md`（含第 14 節異動紀錄）。
- **前端**：`session.html`、`game.js`、`game-state.js`、`game-session.js`、`game-store.js`、`game-api.js`、`turn-stream.js`、`game.css`、`typewriter.js`（以段重用，不改介面）；新增純函式模組（分頁、閱讀狀態機）與其 Node 測試。
- **設定與規範**：沒有新的設定表鍵（每畫面 1 次是固定行為，不是可調設定）；AGENTS.md 第 5、6、7、10、11 節與 skill reference。
- **文件與簡報**：`docs/RPG.md`、前端結構、系統架構、資料模型文件與 `tests/test_design_docs.py`；遊戲畫面相關的四支示範影片過時；`docs/2.0簡報.md`、六張圖解、4.0 簡報若描述遊戲畫面或功能清單需依 `deck-conflict-watch` 通知（只通知、不自行修改）。
- **成本**：每次點 icon 一次短的結構化呼叫（輸入約最近 3 輪加世界狀態、輸出 3 個短句）；因預設不產生，成本只隨玩家主動使用而增加，並受全站每日 token 上限約束。
