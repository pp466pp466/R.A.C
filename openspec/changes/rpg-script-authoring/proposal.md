# Proposal

## Why

RC-1（`rpg-data-and-script`）已經把劇本與存檔的資料、固定規格驗證器和三種內容模式做好，但玩家還沒有任何方式「建立」劇本：沒有暱稱（AGENTS.md 第 10 節要求先有暱稱才能創作）、沒有建立與編輯的 API 與頁面、沒有第 7 節規定的審查層（規則層每次儲存、模型層在送審與開存檔時），也沒有送審次數與劇本數量的限制。少了這一層，RC-8 的審核與公開目錄無從接上，RC-2 的回合引擎也無法保證「未通過審查的劇本不得開存檔」。

這個 change 讓玩家能私下創作劇本、用自己的草稿開存檔，並把草稿送審（進入待審，由 RC-8 核可或退回），同時把審查、限制與暫停機制一次做完整。

## What Changes

- **暱稱與短代號（`users` 新增可為空的欄位）**：暱稱 2 至 20 字，NFC 正規化並去除控制字元，不得含網址、電子郵件或電話的樣式，也不得冒用「官方」；不要求唯一，公開顯示時附系統產生的穩定短代號。新玩家在年齡確認頁與生日、年齡區間**同一步驟**填寫（必填、全有或全無），既有帳號與管理員在帳號設定頁補填，第一次創作劇本前必須已設定。暱稱不進日誌，隨匯出與抹除處理。
- **創作 API 與頁面**：`/api/scripts/*`（建立、讀取自己的、更新草稿、由既有版本建立新草稿、刪除草稿、撤回、重新取用暱稱作為筆名、範例、額度）與 `/scripts` 頁面（Vue 全域變數模式、自製 Modal 與 Toast、離線資產）。頁面含欄位範例帶入與里程碑預覽。更新草稿以內容雜湊偵測衝突。擁有者以外一律 404。
- **審查層（AGENTS.md 第 7 節）**：
  - **規則層**：每次儲存都執行的純函式，詞表為資料檔；只在明確命中四類紅線（未成年的性內容、性暴力、非自願的性情節、真人名義的性內容）時直接拒絕，只回類別；有疑慮者標示類別進人工；一般的未成年角色不得誤擋。
  - **模型層**：真的實作，使用 RPG 用途的模型（`OPENROUTER_MODEL`，不使用 Gemini），非串流結構化輸出，沿用 `run_structured` 的解析與重試規則；用量帳本新增呼叫類別 `script_review`。審查結果記在版本上（對應內容雜湊），內容有變動才重新審查；模型不可用時**一律擋下**（送審與開存檔都拒絕，不放行）。內建劇本視為已審查。
  - 開存檔改為需要「目前內容已通過模型層審查」（`SessionService.start_session` 接上）。
- **送審**：草稿 → 待審（內容凍結）。送審前依序檢查：是否被暫停發佈、當日送審次數、規則層、模型層；通過才進入待審。核可與退回由 RC-8 負責，在那之前待審的劇本停在待審。
- **送審次數、連續被拒與暫停發佈**：送審次數依會員等級、以 Asia/Taipei 日界計；**連續 3 次送審被自動拒絕**（成功送審一次即中斷）就設定獨立的「暫停發佈」旗標，只停止送審，其餘功能不受影響。暫停的帳號可使用申訴頁，管理員可檢視其申訴並在重新輸入密碼後解除，全程寫入稽核。被拒絕的送審只保留類別列舉值與時間（`script_submissions`，12 個月）。
- **申訴捷徑**：玩家被鎖定或被暫停發佈時，所在的頁面（`/cs`、`/scripts`、`/account`）直接顯示「前往申訴」按鈕，不必自己去找申訴頁。判定只依伺服器回應（403 `account_locked`／`publish_suspended` 與 `/api/auth/me`），按鈕是連到 `/appeal` 的一般連結，狀態解除後即消失。
- **限制存在資料庫（`runtime_limits`）**：各會員等級的劇本數量上限、每日送審次數上限與連續被拒門檻存於資料庫設定表，程式**每次現讀**（不放行程快取）；缺值時使用程式內的保底預設；以 `flask set-script-limit`／`show-script-limits` 修改並寫稽核紀錄（管理員欄位為空，細節只有鍵與新舊數值）。
- **規範修訂（待你核可字句後單獨提交，見 design D12）**：AGENTS.md 第 7 節的「沿用帳號鎖定與申訴機制」改為暫停發佈的明確規則、「初始值由設定決定」改為存於資料庫的設定表；第 10、11 節申訴的可讀範圍由「被鎖定」擴大為「被鎖定或被暫停發佈」。**相關的實作（申訴對暫停的擴充）要等字句核可後才開始**，其餘不受影響。
- **銜接生命週期**：匯出納入暱稱與送審紀錄；抹除隨 `users` 串聯；保存期限新增送審紀錄 12 個月。
- **不做**：管理員的審核佇列、核可與退回、公開目錄與搜尋、檢舉、「匿名保留我已發佈的劇本」偏好（RC-8）；回合引擎、SSE、劇情輸出的審查層（RC-2）；遊戲介面（RC-3）；圖片（v1 不做，非空一律拒絕）；管理員後台的額度設定頁（本次只提供 flask 指令）；服務條款與隱私權政策的措辭（留給法務關卡 N-13）。

## Capabilities

### New Capabilities

- `player-nickname`: 暱稱與短代號的規則、設定時機（年齡確認頁、帳號設定頁）、創作前必須已設定、公開顯示格式，以及個資處理。
- `script-authoring`: 玩家創作劇本的 API 與頁面：建立與編輯草稿、衝突偵測、由既有版本建立新草稿、刪除與撤回、筆名重新取用、範例與額度查詢、作者的內容模式上限、擁有者隔離。
- `script-review`: 規則層與模型層審查：類別列舉、誤擋防線、審查結果與內容雜湊的對應、模型不可用時的處置、開存檔前的把關、內建劇本的豁免、提示詞與日誌的限制。
- `script-submission`: 送審流程與次數限制、送審紀錄、連續被拒的計算、暫停發佈旗標、管理員檢視與解除。
- `runtime-limits`: 存在資料庫的限制設定：鍵的集合與範圍、每次現讀與保底預設、修改指令與稽核。
- `appeal-shortcut`: 被鎖定或被暫停發佈的玩家在所在頁面看到「前往申訴」按鈕：由哪些回應判定、在哪些頁面顯示、按鈕的形式、解除後消失。

### Modified Capabilities

- `post-login-age-confirmation`: 「補填年齡確認」新增暱稱為必填，與生日、年齡區間同一步驟，全有或全無。
- `auth-pages`: 「年齡確認頁」新增暱稱欄位與公開顯示的提示；「帳號設定頁」新增暱稱的檢視與更改。
- `lockout-appeals`: 申訴的對象由「被鎖定者」擴大為「被鎖定或被暫停發佈者」，管理員可檢視兩者的申訴。**實作等 AGENTS.md 第 10、11 節字句核可。**
- `cs-chat-ui`: 「被閘門擋下時引導使用者」新增帳號被鎖定時的說明與「前往申訴」按鈕。
- `rpg-sessions`: 「誰可以用哪個版本開存檔」新增模型層審查的把關（取代原本「由後續 change 加入」的括號）。
- `admin-audit-log`: 動作列舉新增 `limit.set`、`publish.suspend`、`publish.lift`。
- `account-deletion`: 抹除的範圍納入暱稱與送審紀錄。
- `personal-data-export`: 匯出納入暱稱、短代號與送審紀錄。
- `data-retention`: 新增送審紀錄保存 12 個月。
- `service-observability`: 新增劇本、暱稱、審查與暫停事件的白名單。

## Impact

- **資料庫**：遷移 `0013_rpg_script_authoring`（只新增，expand 階段）：`users` 新增 `nickname`、`nickname_code`、`publish_suspended_at`（皆可為空）；`script_versions` 新增 `review_hash`、`review_verdict`、`review_categories_json`、`reviewed_at`（皆可為空）；新表 `script_submissions`、`runtime_limits`（遷移以 ORM 寫入預設列）。SQLite 與 SQL Server 雙軌都要通過。
- **程式**：`app/models/`（`User`、`ScriptVersion`、新模型）、`app/repositories/`（劇本新增編輯方法、送審紀錄、限制、使用者的暱稱與暫停）、`app/services/`（暱稱、創作、規則層、模型層、送審、限制、`AccessPolicy` 新閘門、`SessionService` 接審查、`AuthService.verify_age` 接暱稱、`AppealService` 與 `AdminService` 擴充）、`app/controllers/`（`script_api_controller`、`script_page_controller`、帳號與年齡端點）、`app/cli.py`（兩個新指令）、`app/data/review/`（規則層詞表）、`app/templates/scripts/`、`app/static/js/scripts/`、`/age` 與 `/account` 的頁面。
- **LLM**：`llm_call_logs` 新增呼叫類別 `script_review`（沿用 RPG 用途的 `LlmService`）；全站每日 token 與呼叫上限本來就不分類別彙總，審查呼叫自動計入。
- **測試**：規則層（含誤擋案例）、模型層（假模型伺服器與假供應商，不打真實 API）、送審流程與並行、暫停與解除、限制讀取、暱稱驗證與年齡步驟、創作 API 的擁有者隔離、前端純邏輯的 Node 測試、遷移、匯出與抹除的守門測試擴充、容器驗收。
- **文件與規範**：`.env.example` 不變（限制存資料庫）；README（端點表、flask 指令表）、`docs/`（資料模型、系統架構、帳號與安全、模型呼叫層、前端結構、營運與部署、路線圖、RPG.md）；AGENTS.md 與技能鏡像的字句修訂（待你核可）。
- **不影響**：客服（用量額度、限流、提示詞）、登入流程本身、既有的對話資料、RC-1 已建立的資料表結構與狀態機。
