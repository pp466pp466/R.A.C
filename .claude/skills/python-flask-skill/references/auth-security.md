# 身分驗證與安全 (Authentication & Security)

對應 AGENTS.md 第 10 節。

- 登入與 session：採簽章 session cookie（HttpOnly、Secure、SameSite=Lax；正式環境使用 __Host- 前綴），內容只含 user_id 與 token_version；不使用 JWT。有效期為閒置 30 天、每次使用就續期（由框架在每次回應時重新簽章，不另放簽發時間），不設絕對上限：cookie 被竊取後只要持續被使用就一直有效，撤銷靠 token_version。管理員改密碼、登出所有裝置或停權時使 token_version 加 1，以撤銷既有 session。已登入時打開首頁（/）或登入頁，直接導向登入後的預設頁面（單一常數；目前為 /cs，RPG 上線後改為選擇劇本的首頁，不直接進入聊天）；尚未完成年齡確認的玩家則一律導向年齡確認頁。
- 密碼：只有管理員有密碼（玩家不設密碼，只用 Google 登入）；以 Argon2id 雜湊，長度限制 8 至 128 字，不強制字元組合。
- 帳號唯一：一組 email 只能對應一個帳號，email 正規化為小寫後唯一；判斷是否重複時，gmail.com 與 googlemail.com 的信箱另去除「.」與「+標籤」後比對（email_canonical 欄位，同樣唯一），寄信仍使用原始地址。玩家帳號的身分只有 Google；管理員帳號是密碼憑證加綁定的 Google 身分（見合併規則）。帳號刪除後，同一信箱可重新以 Google 登入建立帳號。
- 註冊與驗證：玩家只以 Google 登入，首次登入即註冊（沒有密碼註冊，也沒有信箱驗證信、玩家端的重設密碼信與 EMAIL_VERIFICATION_REQUIRED；信箱是否屬於本人以 Google 回傳的 email_verified 為準，建立帳號時 email_verified_at 即有值）。登入與註冊畫面只有 Google 登入與一個「同意服務條款與隱私權政策」的勾選框：新使用者必須勾選，並記錄 terms_version 與 terms_accepted_at；回訪的使用者不必勾選，一鍵登入。新使用者未勾選時不建立帳號，導回登入頁提示。production 不再因玩家端而要求信箱驗證或寄信服務；營運告警信與管理員的重設密碼信仍需寄信設定（見第 11 節）。管理員帳號的密碼只用於 Google 登入之後的第二道驗證與高風險操作的重新驗證（見下方管理員一條）；管理員忘記密碼時，在密碼驗證那一步按「忘記密碼」，系統寄重設信到該管理員的信箱（與營運告警信走同一組寄信設定），在信件連結的確認頁修改密碼；此按鈕只在管理員通過 Google 之後的那一步出現，不接受匿名請求。重設權杖為 32 位元組隨機值，資料庫只存其 SHA-256 雜湊，單次使用，1 小時失效；連結的 GET 只顯示確認頁，由 POST 完成動作；重設成功後 token_version 加 1 並寄通知信。
- 年齡確認：玩家以 Google 首次登入建立帳號後，須立即填寫生日，並從下拉式選項選擇年齡區間；兩者皆為使用者自行聲明，不蒐集證件、不核實。完成之前，除了完成年齡確認與登出之外不得使用任何功能（由 AccessPolicy 判斷，回 403 與代碼 age_confirmation_required），就像沒有勾選條款不能登入一樣；帳號自建立起最多保留 24 小時，逾時未完成即由排程刪除（見第 11 節）。伺服器由生日計算年齡：未滿 13 歲者不得使用本平台，發現時立即抹除該帳號與其全部個資（走與使用者主動刪除相同的抹除出口），不保存其填寫的生日，只回覆通用訊息；與所選年齡區間不一致時，一律回覆通用的「資料有誤」訊息並要求重新填寫，不保存該次填寫的內容。通過後記錄 birth_date、age_range、age_confirmed_at 與 age_policy_version，並可另記錄當時是否已滿 18 歲的結果（僅供紀錄）；是否已滿 18 歲一律由 birth_date 於當下計算，不以儲存的結果判斷，使用者滿 18 歲後限制自動解除。生日與年齡區間不傳送至 Gemini；管理員後台只提供年齡區間的彙總統計，不顯示個別使用者的生日。13 至 17 歲者可以使用本平台（含 AI 功能），但只能使用安全模式（見第 7 節）並在介面顯示提示；已滿 18 歲者不受此限。管理員帳號（由部署者以一次性指令建立）不受上述 24 小時與全面禁用的限制，可登入與管理帳號，但在完成年齡確認之前不得使用任何會呼叫 Gemini 的功能，由 AccessPolicy 判斷並回 403 與代碼 age_confirmation_required；各會員等級不豁免；管理員於帳號設定頁補填。原因與前提：Gemini API 條款要求使用者年滿 18 歲，且不得用於可能被未滿 18 歲者使用的應用，因此「13 至 17 歲者可使用」是以 Google 同意為前提的設計；Google 不同意時，本條須修訂為未滿 18 歲者不得使用。
- 防帳號列舉：登入失敗（含管理員的密碼驗證）一律回應相同的通用訊息，不洩漏帳號是否存在。管理員改密碼成功後 token_version 加 1。
- Google 登入：採 Authorization Code 流程搭配 PKCE、state 與 nonce；須驗證 ID token 的 iss、aud、exp、nonce，且要求 email_verified 為真；開發與正式環境使用不同的 OAuth 用戶端。發起時只帶新使用者的條款勾選旗標（放進簽章的交易 cookie），回訪的使用者不需要任何欄位；已有帳號者直接登入，沒有帳號而未勾選條款時不建立帳號，導回登入頁提示。管理員通過 Google 之後還須再通過密碼驗證，兩者都通過才建立登入 session；中間狀態只存在短效的簽章 cookie，不能存取任何受保護的資源，管理員也不能只靠密碼登入。
- 同信箱帳號合併：以 email_verified 為前提。管理員帳號（由部署者以指令建立、信箱已驗證）第一次以同信箱的 Google 登入時，直接綁定 Google 身分；玩家帳號沒有本機憑證，沒有合併的情況。已綁定的 Google 身分以其穩定識別（sub）辨識，不因信箱變更而重新比對。
- CSRF：所有非 GET 請求須通過 CSRF 檢查（token 置於頁面 meta，axios 預設帶 X-CSRF-Token 標頭）並驗證 Origin。不得使用需載入外部腳本的驗證碼服務（違反離線前端架構）。
- 登入失敗限制：管理員同一帳號的密碼連續失敗 5 次鎖定 15 分鐘，計數存放於資料庫。
- 帳號鎖定：玩家帳號有「鎖定」狀態，由系統自動鎖定、只有管理員能解除（不會自動解除）。觸發條件（任一）：同一帳號 15 分鐘內 Google 登入被拒（已辨識出身分但被拒絕，例如帳號停用、年齡資料不符）達 5 次；同一帳號 15 分鐘內被每分鐘訊息數上限擋下達 10 次（客服洗版）。無法辨識身分的失敗（例如授權碼或憑證無效）與還沒有帳號的 Google 身分不計入鎖定，只記錄日誌，對匿名濫用的第一道防線是入口層限流（見第 9 節）。被鎖定的玩家仍可通過 Google 登入，但只得到受限登入狀態：只能進申訴頁向管理員留言（單則上限 1000 字、同一帳號每小時最多 3 則、同一時間最多 1 則待處理），其他頁面與 API 一律回 403 與代碼 account_locked。管理員可在後台檢視被鎖定的帳號與其申訴內容並解除鎖定；管理員只能看到被鎖定帳號送出的申訴，仍不得任意讀取其他對話全文；鎖定、申訴與解除都寫入稽核紀錄 (admin_audit_logs)。
- 輸入限制：客服單則訊息上限 1000 字（以 Unicode 字元計），送出前去除控制字元並做 NFC 正規化，空白訊息在 Service 層擋下，不呼叫 Gemini。
- LLM 安全：指令只放在 Gemini 的 system_instruction，使用者文字不得串接進指令；玩家撰寫的個性、角色與世界文字同樣視為使用者文字（記事簿內容，含由玩家文字抓取的重點，亦同），只能以資料區塊放在使用者內容區，不得進入 system_instruction；System Prompt 內放不公開的標記字串，輸出若包含則視為驗證失敗；客服 v1 不提供工具呼叫 (function calling)。reply_text 一律以純文字渲染，嚴禁 v-html。客服：同一使用者一日內被內容安全過濾阻擋達 3 次，暫停對話 1 小時並記錄。RPG：被擋的回合顯示劇情轉場文字而非錯誤、標記為中斷且不進入上下文、自動重新生成一次並記錄；暫停對話的計數只計玩家輸入被擋的次數，模型輸出被擋（多為誤判）不計入，並須記錄結束原因與被擋類別。
- 資料隔離與權限：
  - 所有對話相關的 Repository 方法簽名必須接收 user_id，查詢一律帶 user_id 條件，不提供只憑 ID 取資料的方法給 API 路徑使用；Service 層以 AccessPolicy 集中判斷擁有者與管理員權限，Controller 不自行寫權限判斷。
  - 非擁有者存取一律回 404（非 403），避免洩漏資源是否存在。
  - 角色僅 user 與 admin。管理員存取他人資料須走專用的 Repository 方法，並寫入稽核紀錄 (admin_audit_logs)。
  - 管理員後台為獨立的 /admin 頁面與 /api/admin/*，僅 role 為 admin 者可存取，功能含停權、查看用量與刪除違規內容。首位管理員由部署者以一次性 flask 指令建立（信箱與密碼）；管理員每次登入都先以 Google 登入，第一次以同信箱登入時綁定 Google 身分，通過後再驗證一次密碼，兩者都通過才建立 session。管理員預設只能檢視統計資料、使用者主動提交的意見回饋對話、被鎖定帳號送出的申訴、被內容安全過濾標記的對話，以及待審的性格原型草案（僅含去識別後的草案內容，不含對話全文），不得任意讀取其他對話全文；停權、刪除內容與調整會員等級等高風險操作須重新輸入密碼。
- 用量控制：每位使用者設有速率限制與每日對話輪數上限（依會員等級）；另設全站每日 token 上限，達 80% 告警、達 100% 以繁體中文回覆系統忙碌文案。計數以資料庫帳本 (llm_call_logs) 彙總，fallback 訊息不計入；日界以 Asia/Taipei 計算（資料庫存 UTC）。同一對話同時只處理 1 則訊息。超額與限流的回覆文案一律為繁體中文。
